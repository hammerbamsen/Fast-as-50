## Kendte risici
- **Første rigtige kørsel kan kassere svaret** pga. den strenge talvalidering (fx modellen skriver "8 %" for `hrvVsAvg7Pct: -8` → OK via abs; men "ca. 7 point" for 7,4 → OK via heltalsafrunding; "0,25 kg/uge" når rules siger 0.25 → OK; et regnet tal som "4,2 kg til målet" når konteksten har 72,2 og 68 → KASSERES). Fallback: forrige `data.coach` beholdes (`stale: true`, `validationError` sat og synlig i "Coachen er ikke opdateret"-linjen og i FORÆLDET-banneret via `coachAssessmentError`); Én ting falder tilbage til advarsel/coachHighlight (regelbaseret `generate_coach_speech` kører stadig). Løsning hvis det sker ofte: læg de manglende afledte tal i konteksten (fx `weightToGoal` findes allerede) frem for at slække på validatoren. `SMALL_INT_OK = 7` kan justeres i `coach_validate.py`.
- Konteksten sendes som JSON → flere tokens end før på hverdage (~+2 000 tegn) og søndage (~+4 000). Ét kald i stedet for to opvejer en del.
- `inputsHash` ændrer sig ved enhver ny måling (fx HRV om morgenen) → `data.coach.stale` bliver true indtil næste generering (max 6 t, eller tidligere ved vægt/fedt/AF/aktivitet/plan-ændring som før). Det er ærligt, men UI'et viser det kun som en lille linje.
- `weekFocusNext` fra søndag bruges mandag kun hvis `programId` matcher; ved programskiftet 6→7/9 regnes næste program/uge eksplicit (tds-2027 uge 1).
- AI-advarslers `action.edit` valideres kun mod id'er i konteksten — selve redigeringen går stadig gennem Plan-arket, Friel-gaten og plan-edit.yml (ingen auto-udførelse).
- `data.json` er ikke regenereret; `data.coach` findes først efter næste `update_kpi.py`-kørsel. Indtil da: fallback-adfærd som i blok 3/4.
- `plan.html` læser ingen coach-felter (verificeret med grep) — kun index.html påvirkes. Eksterne læsere af `coachAssessmentHtml` får nu klasser (`.coach-head/.coach-sec/.coach-sec-h`) i stedet for inline styles.
